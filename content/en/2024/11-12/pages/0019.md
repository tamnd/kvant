The 2nd stage recursion is interesting because it is *not fundamentally free* from primitive recursion. Let us explain and clarify this fact. Let us denote by $F(n,x,y)$ the function $x \uparrow^n y$. We will conduct recursion using the arguments $n$ and $y$. Let's set the following recursion scheme of the 2nd stage:

$$F(1,x,y) = x^y,$$
$$F(n+1,x,1) = x,$$
$$F(n+1,x,y+1) = F(n,x,F(n+1,x,y)).$$

The argument $x$ in this definition is functional, so let’s consider how the function $F$ depends on the other two arguments. The first line corresponds to specifying the function $F$ on pairs of the form $(1,y)$. The second line defines the function $F$ on pairs of the form $(n+1,1)$ - these are precisely those pairs that do not have a direct representing pair. Finally, the third line expresses the function $F$ on the pair $(n+1,y+1)$ through the values ​​of the function $F$ on the pairs $(n+1,y)$ and $(n,F(n+1,x,y))$. Both of these pairs are lexicographically smaller than the pair $(n+1,y+1)$, so this scheme is an example of a well-defined 2nd stage recursion scheme.

It turns out that the function $F$ is not a primitive recursive function: it is impossible to define it, use elementary functions and operations of composition and primitive recursion. The reason is this. Let us denote by $A(x)$ the function $F(x,2,x)$. The function $A$, by its definition, is very close to the Ackermann function (more precisely, to the version of Roja Peter, which simplified the original construction of Ackermann, for more details see [3]). For functions $A$ the following theorem is true.

**Theorem.** Let $f$ be any primitive recursive function of one argument. Then find a number $n$ such that the inequality $f(x) < A(x)$ holds for all numbers $x > n$.

From this theorem it follows that the function $A$ is not primitively recursive (otherwise, taking $A$ as $f$ in the formulation of the theorem, we would come to a contradiction). This means that the function $F$ is also not primitively recursive, since $A$ can be obtained from $F$ using the composition operation and elementary functions.

It is interesting to note that the coin game described in the original problem models the calculation of the Ackermann function. Namely, to calculate the value of $A(n)$ you need to take $n + 2$ boxes and put $n$ coins in the first box. Then the permitted operations can produce $A(n)$ coins in the second box (see Lemma 3).

When calculating the Ackerman function, recursive calls of enormous depth appear. Therefore, the Ackerman function is used to test the compiler's ability to optimize recursion. Also, functions like the Ackerman function appear as measures of the time complexity of some algorithms.

For further study of this topic, we recommend a series of lectures by L.D. Beklisheva “Fast-growing function (“fast, higher, stronger”)”, read at the summer school “Modern Mathematics” in Dubna in 2012.
