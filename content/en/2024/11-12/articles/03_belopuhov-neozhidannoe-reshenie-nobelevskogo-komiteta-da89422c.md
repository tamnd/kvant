The 2024 NOBEL PRIZE IN PHYSICS is awarded “for fundamental discoveries and inventions that enable machine learning with artificial neural networks.”

This decision came as a complete surprise to physicists. After all, the terms “machine learning”, “artificial neural networks” as separate aspects of “artificial intelligence” belong not to physics, but to informatics. But there is no non-Belev nomination for informatics. And although non-Belev prizes in physics were sometimes awarded in cosmology, and for laser instruments, and for fiber optics, this is still close to physics. But informatika...

Moreover, information science, non-beleutical research and achievement have their own merits. The simplest of them is the Alan Thøring Prize. The association consists of 35 sections, which include scientists from many countries around the world. There are separate sections on artificial intelligence and machine-human communication. The Thøring Prize is equal in amount to the non-Belev Prize and is considered to be not inferior to it in terms of representativeness. Over 58 years, it has been awarded to 81 scientists. Is it possible to go to infinity?

It's amazing how from a fairly small number of coins (originally there were only 6) the operation columns can yield at least $^{16}2$ coins! To get an idea of ​​how huge this number is, note that $^{5}2$ already contains almost 20 thousand digits in decimal notation! A natural question arises: is it possible to get as many coins as you like in one of the boxes, or is the number of coins limited from above by some number?

First, we will prove that for any initial number of boxes and any arrangement of coins in them, it is impossible to perform the actions allowed in the task for any length of time. Let there be $n$ boxes. We will denote the situation that we receive in the course of our actions in the form of an ordered sequence of length $n$ of non-negative integers: $(a_1, \dots, a_n)$ ($a_i$ denotes the number of coins in the $i$-th box).

Let us consider the order on such sequences, called lexicographical. This is the perfection of natural order in words (i.e. sequences of letters of some alphabet), this is how words are ordered in dictionaries and reference books so that the words you need are easy to find. Let's figure out what kind of order this is. In order to compare the sequences $(a_1, \dots, a_n)$ and $(b_1, \dots, b_n)$, you first need to compare $a_1$ and $b_1$ (just like numbers). If $a_1 < b_1$, then the first sequence is less than the second, if $a_1 > b_1$, then the first sequence is greater than the second. If $a_1 = b_1$, then you need to compare $a_2$ and $b_2$, etc. Formally, $(a_1, \dots, a_n) < (b_1, \dots, b_n)$,

if there is such a $k$ such that
$$\begin{cases} a_1 = b_1, \\ a_2 = b_2, \\ \dots \\ a_k = b_k, \\ a_{k+1} < b_{k+1}. \end{cases}$$

Note that in our definition, only sequences of the same length can be compared, in contrast to the natural lexicographical order in words. Sequences of different ones should be compared like this: $(a_1, \dots, a_n) < (b_1, \dots, b_m)$, if either there is a $k$ such that the previous system is fulfilled, or $(a_1, \dots, a_n)$ is the beginning of the sequence $(b_1, \dots, b_m)$.

On the other hand, the lemma we will prove below turns out to be false if we allow sequences of different lengths to be compared.

**Lemma 1.** For lexicographic order on a sequence of length n, there are no infinitely killing chains, m.e. there are no sequences for which this is done

$$\left(a_1^1, \ldots, a_n^1\right) > \left(a_1^2, \ldots, a_n^2\right) > \ldots > \left(a_1^m, \ldots, a_n^m\right) > \ldots$$

**Proof.** Let's assume that such an infinitely killing chain exists. Let's look at the first terms of these sequences $a_1^1, a_2^1, \ldots$. These numbers do not increase, therefore, starting from a certain moment, this sequence will stabilize (there will be no strict killing). Let's consider this moment and reverse the finite number of terms of the sequence that precede it, redesignating the indices if necessary. Thus, now in all sequences the first term is the same. Let us consider the second terms of these sequences $a_1^2, a_2^2, \ldots$. For the same reasons, starting from a certain point, they stabilize. Let's consider this point. Having repeated the same reasoning n times, we come to the conclusion that all n terms stabilize at some point, which contradicts the strict killing in lexicographical order. The lemma is proven.

Using this lemma, we prove that if we start with some initial arrangement of coins in the boxes, then the number of coins we will add up is bounded from above. We will not give any (further rough) estimates for this upper bound. The proof will be based solely on general messages related to finite and infinite.

We will imagine the possibility of arranging coins in boxes in the form of tree tops. The root of this tree is the original arrangement of the coins. An arrow leads from an ancestor to a child if the sequence of coins stored in the child can be obtained from the sequence of coins recorded in the ancestor using one of two permitted operations.

Let's make two important remarks about obtaining a tree.

• Lemma 1 means that there are no infinite paths in this tree.

• In this tree, from each vertex there is a finite (further limited from above by a single number) number of arrows leading to descendants. This quantity is trivially estimated from above by the number $2n - 3$ (no operations can be performed on the last box, only the first operation can be performed on the penultimate box, and no more than 2 different operations can be performed on all the others). Thus, we are dealing with a finite time tree.

To complete the proof, it remains to apply Köngig's lemma. This statement, which is not difficult to prove, plays an important role in mathematical logic.

**Lemma 2 (Köngig).** In an infinite tree with finite time, there is an infinite path.

From Köngig's lemma it follows that our tree must be finite: if it were infinite, then, since it has finite branching, it would have an infinite path. Thus, since our tree with possible arrangements of coins is finite, then the number of coins in the boxes (both overall and in each specific box) will necessarily be limited from above.

**Primitive recursive functions**

In our problem, where does the columnar increase in the number of coins come from as the number of boxes increases? You need to take a closer look at the construction of a function of the form $x \uparrow^n y$: each next one is obtained by repeated iteration of the previous one. It is interesting that with the help of such a recursive procedure, many quite interesting functions can be obtained from a small set of simply arranged functions.

First of all, note that all two-argument functions of the form $f(x,y) = x \uparrow^n y$ ($n$ is fixed, and the function arguments are the natural numbers $x$ and $y$) have an interesting feature. Calculating their values ​​requires recursion over only one argument and a few more simple functions and operations. Let's define everything carefully.

We will assume that all functions are defined on the set $\mathbb{N}_0 = \mathbb{N} \cup \{0\}$ and take values ​​in the same set. Additionally, functions can depend on 0 arguments (in which case they are constant functions). Let us introduce notation for the following functions that will represent the elements:

$o(x) = 0$ (identical field);

$s(x) = x + 1$ (adding units);

$I_m^n(x_1,\dots,x_n) = x_m$ for $1 \leq m \leq n$ (procedure functions).

Let's consider two operations on functions. The first operation is a composition of several functions. This operation generalizes the well-known function composition operation $g(f(x))$. Let us be given functions $f_1,\dots,f_n$, depending on $m$ arguments, and also functions $g$, depending on $n$ arguments. Their composition $K[g,f_1,\dots,f_n]$ is a function dependent on $m$ arguments. It will be defined like this:

$$
K[g,f_1,\dots,f_n](x_1,\dots,x_m) =
g(f_1(x_1,\dots,x_m),\dots,f_n(x_1,\dots,x_m)).
$$

The second operation - using recursive - is arranged in a more cunning way.

Let us denote this operation by the letter $R$, then $h = R[f, g]$. Primitive recursion is carried out based on one argument (the last one). Since we have at our disposal a projection function $I_m^n$ and a composition operation, applied recursion can be carried out on any argument. Function $f$ sets the initial value of the recursively defined function $h$, and function $g$ allows a recursive call. Typically, the value of function $h$ on arguments $x_1, \ldots, x_n, y+1$ depends on the value of function $h$ on arguments $x_1, \ldots, x_n, y$, as well as on the arguments $x_1, \ldots, x_n, y$ themselves.

Functions that can be assembled from element functions and composition operations and applied recursion are called primitive recursive functions.

Let us show that the functions we have previously encountered are primitively recursive. As mentioned above, the addition operation is obtained by repeating the operation of adding one. You can write this in a purely recursive way, using elementary functions:

$$x+0 = x = I_1^1(x),$$
$$x+(y+1)=(x+y)+1=s(x+y).$$

Formally, to assemble a two-place function $x+y$ using a primitive recursion operation, we need a one-place function and a three-place function. A single function (which sets the initial value) already exists - this is $I_1^1$. The ternary function $g(x,y,z)$ should behave like $s(z)$. Such a function can be assembled from element ones using the composition operation, namely

$$g(x,y,z)=s\left(I_3^3(x,y,z)\right)=K\left[s,I_3^3\right](x,y,z).$$

From here we finally get that

$$x+y=R\left[I_1^1,K\left[s,I_3^3\right]\right](x,y).$$

Similarly, it is proved that multiplication and exponentiation are also primitive recursive functions. The multiplication function is obtained by repeating the addition operation and therefore satisfies the following primitive recursion scheme:

$$x\cdot 0=0=\mathbf{o}(x),$$
$$x\cdot(y+1)=x\cdot y+x.$$

Considering that we have already proven the primitive recursiveness of the addition function, we find that the multiplication function is also primitively recursive. In other words, the function $x\cdot y$ satisfies a primitive recursion scheme with the following functions:

$$f(x)=\mathbf{o}(x),g(x,y,z)=z+x.$$

represent a primitive recursive circuit with functions

The 2nd stage recursion is interesting because it is *not fundamentally free* from primitive recursion. Let us explain and clarify this fact. Let us denote by $F(n,x,y)$ the function $x \uparrow^n y$. We will conduct recursion using the arguments $n$ and $y$. Let's set the following recursion scheme of the 2nd stage:

$$F(1,x,y) = x^y,$$
$$F(n+1,x,1) = x,$$
$$F(n+1,x,y+1) = F(n,x,F(n+1,x,y)).$$

The argument $x$ in this definition is functional, so let’s consider how the function $F$ depends on the other two arguments. The first line corresponds to specifying the function $F$ on pairs of the form $(1,y)$. The second line defines the function $F$ on pairs of the form $(n+1,1)$ - these are precisely those pairs that do not have a direct representing pair. Finally, the third line expresses the function $F$ on the pair $(n+1,y+1)$ through the values ​​of the function $F$ on the pairs $(n+1,y)$ and $(n,F(n+1,x,y))$. Both of these pairs are lexicographically smaller than the pair $(n+1,y+1)$, so this scheme is an example of a well-defined 2nd stage recursion scheme.

It turns out that the function $F$ is not a primitive recursive function: it is impossible to define it, use elementary functions and operations of composition and primitive recursion. The reason is this. Let us denote by $A(x)$ the function $F(x,2,x)$. The function $A$, by its definition, is very close to the Ackermann function (more precisely, to the version of Roja Peter, which simplified the original construction of Ackermann, for more details see [3]). For functions $A$ the following theorem is true.

**Theorem.** Let $f$ be any primitive recursive function of one argument. Then find a number $n$ such that the inequality $f(x) < A(x)$ holds for all numbers $x > n$.

From this theorem it follows that the function $A$ is not primitively recursive (otherwise, taking $A$ as $f$ in the formulation of the theorem, we would come to a contradiction). This means that the function $F$ is also not primitively recursive, since $A$ can be obtained from $F$ using the composition operation and elementary functions.

It is interesting to note that the coin game described in the original problem models the calculation of the Ackermann function. Namely, to calculate the value of $A(n)$ you need to take $n + 2$ boxes and put $n$ coins in the first box. Then the permitted operations can produce $A(n)$ coins in the second box (see Lemma 3).

When calculating the Ackerman function, recursive calls of enormous depth appear. Therefore, the Ackerman function is used to test the compiler's ability to optimize recursion. Also, functions like the Ackerman function appear as measures of the time complexity of some algorithms.

For further study of this topic, we recommend a series of lectures by L.D. Beklisheva “Fast-growing function (“fast, higher, stronger”)”, read at the summer school “Modern Mathematics” in Dubna in 2012.
