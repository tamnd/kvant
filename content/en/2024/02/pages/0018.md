The shift cipher is sometimes called a Caesar cipher because Julius Caesar used such a cipher with $b = 3$.

A shift cipher is an example of a private key cryptosystem. Such cryptosystems differ in that the same key is used for both encryption and decryption, therefore such cryptosystems are called symmetric.

With symmetric encryption, both the sender and the recipient must know the key. However, the problem arises of how to tell each other the secret key so that he does not recognize the construction. This problem was solved using asymmetric cryptography (public key encryption) methods.

Public key cryptography
The difference between public key cryptography and classical cryptography is that when using keys, it is difficult to obtain the decryption key from the encryption key. This means that the encryption key does not need to be kept secret. You can tell the whole world what encryption key to use in order to encrypt a message, while keeping the decryption key secret. As a result, there is no need to first establish a communication channel between the sender and the recipient in order to securely transfer the secret key that is needed to encrypt information.

Public key cryptography began with the work of American cryptographers W. Diffie and M. Hellan in 1976.

In a public key encryption scheme, there are two keys - the public key, denoted by the letter $e$, and the secret key, denoted by the letter $d$. The encryption function $E_e$ uses the public key, and the decryption $D_d$ uses the secret key.

Decrypting a message without knowing the secret key is practically impossible, i.e. the function $f$ is irreversible from the point of view of practical computation. Such easily computable functions, for which the inverse function is difficult to calculate unless it has some additional information, are called one-way functions with a secret.

The following examples can be given to demonstrate what public key encryption is (see [3]).

Let there be a larger telephone directory in which there are surnames for all letters of the alphabet, including “ь”, “ъ”, “ы”. Each surname is assigned to a thousand telephone numbers. Let's assume that there are no computers to work with this directory. We will take a letter of plaintext and encrypt this letter with some telephone number, referring to a surname starting with this letter. From plaintext consisting of letters, you get ciphertext consisting of telephone numbers.

Costs a certain amount of success, but it is still possible to restore the original plaintext. To do this, you need to find a given phone number, see what surname it corresponds to, restore the letter and do this with all the letters.

You can also pre-compile another telephone directory that does not contain telephone numbers. Then the decryption procedure will take less time. A telephone directory in which there is no data by last name is the discovery key used in encryption. The telephone directory, which is missing numbers, is the private key that will be used by the one who decrypts the text.

The main question in public key encryption is: how to come up with a suitable one-way function?

It may seem surprising, but, despite all the variety of the most ingenious methods of encryption and decryption, which throughout have been developed by the most sophisticated minds, the mathematical description of any of them is based on only one mathematical concept - the concept of a one-way function.
