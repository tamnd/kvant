For each vertex v in a directed graph G, we define the in-degree of a vertex v as the number of edges going into v, and the out-degree of v as the number of edges going out of v. We are now ready to formulate Euler's result as applied to directed graphs. Euler's second theorem. The presence of an Euler cycle in an oriented graph G is equivalent to the fact that each vertex of G has equal incoming and outgoing degrees (recall that the graph is assumed to be connected). A proof of Euler's second theorem is given at the end of this article, along with a discussion of how one can find an Euler cycle fairly "fast" in the sense of computer theory. The main idea is that we do not need to check all possible cycles in a directed graph G one by one in order to understand whether G contains an Eulerian cycle. It is enough just to count the incoming and outgoing degrees of all vertices: if each vertex has the same incoming and outgoing degrees, then an Euler cycle can be easily constructed; if there is at least one vertex whose incoming and outgoing degrees are different, then it is impossible to carry out an Euler cycle.

Solvable and unsolvable problems

⟦column⟧

Inspired by Euler's theorem, we can ask whether a similar simple result exists for solving the GZ. But despite the fact that winning the “Icosahedral Game” is not so difficult, the solution to the GC for an arbitrary graph remains unknown. The main difficulty is that if we have Euler’s theorem for solving the ZEC, then for the ZGZ a similar simple condition is unknown. Of course, you can always use the “brute force” method to solve the ZGC, i.e. program the computer to iterate through all the paths in the graph and report as soon as it finds a Hamiltonian cycle. This method is quite easy to understand, but imagine a huge graph that does not have a Hamiltonian cycle. For this graph, the computer will have to check every path along it before telling you that there is no Hamiltonian path. The catastrophic flaw of this method is that in the average graph of just a thousand vertices there are more different paths than there are atoms in the universe! ZGZ was one of the first algorithmic problems that even the most brilliant scientists could not solve. After many years of fruitless efforts, computer scientists began to wonder whether the ZGC was effectively decidable. In other words, could it be that their failure to find a fast algorithm is caused not by a lack of intelligence, but by the fact that an effective algorithm for solving the ZGC simply does not exist. Moreover, in the 1970s, computer scientists discovered thousands more different algorithmic problems with the same fate as ZGC: despite the fact that they looked extremely simple, no one could come up with an effective solution for them. ZGCs, together with many of these problems, are now called $«NP-полными»^{2}$ problems. Further adding to the disappointment caused by the failure of all attempts to find a simple condition for the solvability of the GZ, is the following fact: although all NP-complete problems are different, it turns out that they are all equivalent to each other - if you find a fast algorithm for solving one such problem, then it will automatically result in a fast algorithm for all the others! The problem of efficiently solving NP-complete problems (or conclusively proving that such a solution does not exist) is so fundamental to computer science and mathematics that it was included in the Clay Mathematics Institute's "Millennium Challenge" list, published in 2000: find an efficient algorithm for some NP-complete problem, or prove that there is none, and the institute will award you a million-dollar prize. From now on, we will call the ZEC “simple” and the ZGC “complex.” Don't forget this difference, because it will soon become critical.

2 NP – from the words non-deterministic polynomial (English).
