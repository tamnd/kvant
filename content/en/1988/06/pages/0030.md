M1086. With a number cut, perform two operations: “increase by 2 times” and “increase by 1”.
For what is the smallest number from the number 0 to get: a) the number 100? b) number n?

a), 6) It is convenient to solve the problem from the end, that is, to look for the shortest way to obtain the number 0 from an arbitrary natural number n using two operations - subtracting 1 (B) and halving (D). Let r(n) be the number of operations B and D in such a shortest algorithm. If n is odd, then only operation B can be applied to it, so

$$r(2k+1)=1+r(2k).$$

Let us show by indication of k that r(2k)=1+r(k), i.e., an even number in the shortest algorithm must be divided in half. For k=1 this is clear. Let this be proven for all numbers less than k. If we first apply the operation B to the number 2k (subtract 1), then the number of operations before obtaining 0 will be no less than

$$1+r(2k-1)=2+r(2k-2)=3+r(k-1)$$

(according to indication assumption). If we first divide 2k in half, and further along the optimal path, then the number of operations will be 1+r(k)≤2+r(k-1). So the second way depends.

To find out how many operations are required in the shortest algorithm for a given number n, we represent n as a sum of powers of two: $n=2^{k_1}+2^{k_2}+...+2^{k_m}$, where $k_1$ is non-negative, and $k_2$, ..., $k_m$ are positive integers ($k_1, k_1+k_2,...$ are the numbers of double notation digits of n in which there is a unit). Then

$$r(n)=k_1+r(n/2^{k_1})=k_1+1+r(2^{k_2}+...+2^{k_m})=...$$

$$...=(k_1+1)+(k_2+1)+...+(k_m+1)=$$

$$=(k_1+k_2+...+k_m)+m=[\log_2 n]+m$$

([x] is the integer part of x), since $k_1+k_2+...+k_m$ is the exponent of the most powers of two, not exceeding n. Note that m is equal to the number of entries of the number n. In particular, for n=100 we obtain the answer to problem a): $r(100)=9$.

The margin shows the transformation of the number 100 into 0 in decimal and double notation. Since $100=2^6+2^5+2^2$, we get $r(100)=6+3=9$.
