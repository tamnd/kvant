机器语言

计算机的机器语言只不过是其机器指令的系统（参见 «Kvant»，1981，第 4 期 - “三地址、单地址和……无地址机器”）。机器“理解”这些命令的规则嵌入在计算机的设计中，就像自动化的设计嵌入在“理解”转动方向盘的“含义”中一样。

让我们举一个该语言所使用的程序的工作示例。假设这位程序员在解决问题的过程中必须计算出在下落开始后$T$秒内自由喂食矩阵点位于什么高度$H$，如果该点的初始高度为$A_m$，则初始速度为$V_m/c$。相应的物理公式是众所周知的：

$$H = 9,81 \cdot T^2/2 + V \cdot T + A,$$

但对于程序员来说，以不同的形式重写它会更方便：

$$H = (9,81 \cdot T/2 + V) \cdot T + A.$$

在开始编写程序时，程序员必须为其执行“内存分配”，即确定将用于存储某些数量的单元的地址。

举个例子，他分配的内存如下：

| 震级 | 小区地址 |
| :--- | :--- |
| 恒定9.81 | 1001 |
| 常数2 | 1002 |
| 变量$A$ | 1101 |
| 变量$V$ | 1102 |
| 变量$T$ | 1103 |
| 变量$H$ | 1104 |

进一步，在我们的机器上（顺便说一下，这是当之无愧的国产计算机技术之风——M-220机器，至今在一些地方仍在使用）加法运算的代码为01，除法 - 04，乘法 - 05。然后，按照他的所有程序，例如从单元格0101开始，程序员写道：

$$Y = E'9.81;T,H$$
$$D = E'2';H$$
$$C = H,V,H$$
$$Y = H,T,H$$
$$C = H,A,H$$

（C - 加法，Y - 乘法，D - 除法；使用结构 = E'...' 描绘了一个数值常数）。

在这个例子中，作者的便利性和缺点都显而易见。一方面，程序不再关心任何地址。通过更改一个程序或将多个程序合并为一个程序，使不同的程序不会具有相同的名称，并且可能不会注意它们在内存中的移动。但是，另一方面，autorok 中的文本仍然与机器语言中的文本太接近；其中的动作对于数学来说太小而且不寻常。

无论作者的水平有多低，用它编写的程序都无法被机器直接感知，它们和任何其他编程语言编写的程序一样，必须先翻译成机器语言才能使用。对于这种翻译（广播），已经开发了特殊程序 - 翻译器。自动记录的翻译程序称为汇编程序。作者对机器语言的接近确保了汇编程序的相对简单性。

Fortran 和 ALGOL

第一种独立于机器的语言是 Fortran，旨在用于编程计算任务。它于 1956 年在美国创建。 1958-1960年，一群来自不同国家的数学家出于相同的目的开发了ALGOL-60语言。这两种语言仍然在世界各地广泛使用。计算数学应用各个领域的大量程序都是用它们编写的。这些语言在很多方面都有所不同，但我们在这里不会触及它们的差异。让我们回到我们的例子。我们会很高兴地知道，要计算原始值，现在只需一个运算符就足够了：

$$H = (9,81 * T/2 + V) * T + A$$

（用 Fortran 语言编写的示例）。

专业语言

计算任务也不同。这些可能是工程和科学技术问题，需要对相对少量的数据进行大量计算。 Algol-60 和 Forteran 非常适合这些目的。还有会计、经济和会计任务，其中任意操作很简单，但必须处理大量且复杂的组织信息，例如工资记录。对于此类任务，Cobol 语言早在 1960 年就已开发出来。Cobol 中的程序指定输入和输出文档信息的格式（排列方式），并使用与英语（或俄语）语言中的短语接近的短语来确定必须对该信息中包含的数值和文本执行哪些操作。

与此同时，以文本或其他非数字（符号）信息处理为中心的任务也很常见。函授编程学院的一课（«Kvant»，1980，第11期）专门讨论了此类问题，但我们将通过提及另外两圈问题来稍微扩展本课的主题。

另一范围的任务是将编程应用于编程本身。用任何语言编写的程序都需要进行各种类型的编辑，最重要的是，翻译成机器语言。但程序是文本，所有这些任务都属于文字处理领域，而文字处理往往是复杂而具体的。有许多语言被设计用来处理文本。纳米球是其中最著名的。

一些编程语言的特点与其说是其应用领域，不如说是其所处理的数据的结构。这就是 Liss，一种专门为处理列表中组织的信息而设计的语言。列表与一维数组的不同之处在于它更灵活。它的长度不是预先固定的，可以在任何地方补充新元素，也可以从任何地方删除元素。实际上，这意味着列表的元素在内存中的位置并不相互靠近（数组通常是这种情况），但每个元素都提供了一个链接，指示下一个元素所在的位置。很明显，列表中的本地更改不会导致列表的内存修改 - 仅个别链接发生更改。

通用语言

自 60 年代中期以来，随着创建专门的编程语言的愿望，出现了相反的愿望：通用语言开始出现，适用于任何任务 - 工程或会计、编辑或翻译 - 具有处理信息的派生结构。

这里使用的“通用语言”这一表述的理解并未被普遍接受。

我们可以立即说，在现代，专业语言和通用语言之间不存在赢家。两种语言在某些情况下都很好，而在另一些情况下则很糟糕。如果程序员经常必须从一类问题转移到另一类问题，或者如果在同一任务中需要执行复杂的计算和编辑文本，那么当然有必要使用通用语言。另一方面，很明显，如果您正在处理某些有限类型的工作，那么启动笨重的通用工具是没有意义的。在通用编程语言中，提到了 PL/1、Algol-68、Settle 和 Pascal。

粗略地说，我们可以说PL/1来自Fortan，而Algol-68的前身是Algol-60。 PL/1 和 ALGOL-68 可以以复杂的方式处理按权重组织的数据。例如，您可以定义一个其元素为列表的数组，其中每个列表依次由一个整数、一串字符、一个数值数组、一个整数单词等组成。Algol-68 的另一个特点是程序员可以在其程序中为语言操作（例如，使用其通常的 + 符号进行加法）赋予新的或附加的含义（例如，允许数组相加），以及定义新的操作。程序员还可以通过定义某类问题所需的一组新操作，使该组可用于解决此类问题的所有程序。因此，ALGOL-68 被证明是一种自我扩展的语言，并且（因为可以出现新的操作）同时自我调整（针对特定的应用领域）。
