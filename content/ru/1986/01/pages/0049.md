можно подобрать такие начальные данные $a_1, \dots, a_n$, b, что применение к ним алгоритма A потребует не менее $\log_2(n+1)$ сравнения.

Доказательство. В качестве $a_1, \dots, a_n$ возьмем любые целые числа такие, что $a_1 < \dots < a_n$, в качестве b будем поочередно сравть $a_1, \dots, a_n, a_{n+1}$. Применение $A_1$ этим вариантом начальных данных должно давать соответствие числа 1, ..., $n+1$. Результаты сравнения, выполненных в ходе применения $A_1$ к любому из этих вариантов, могут быть записаны в виде последовательности слов «да» и «нет». Для исследования значений $a_1, \dots, a_n$ и различных b используются только сравнения вида (1). Поэтому, если применение $A_1$ к начальным данным $a_1, \dots, a_n$ b потребовалровно k сравнений, притом k первых сравнений в ходе применения $A_1$ к другим начальным данным $a_1, \dots, a_n, b'$ должны те же самые результаты, то дальнейшее применение $A_1$ к $a_1, \dots, a_n, b'$ уже не потребует сравнения, и этот будет тем же самым, что и для начальных данных $a_1, \dots, a_n, b$. Следовательно, средние получившихся последовательностей «да» и «нет» нет совпадающих и ни одна не является началом другой. Пусть $l$ — число элементов в самом длиной из этих последовательностей, то есть $n+1$, не превыходит числа всех последовательностей длины l, то есть $2^l$. Итак, $n+1 \leq 2^l$ и $l \geq \log_2(n+1)$. Так как $l$ — целое число, то $l \geq \log_2(n+1)$.

Соопоставление двух доказанных теorem показывает, что не существует такого алгоритма поиска места элемента, который для любых начальных данных требовал бы меньше сравнения, чем алгоритм $A_1$. В этом смысле $A_1$ является оптимальным (напущим) алгоритмом.

Задача 2. Пусть $a_1 < \dots < a_n$ и средние чисел $a_1, \dots, a_n$ есть число, равное b. Требуется найти t, для которого $a_t = b$. Приведите такой алгоритм решения задачи, который требует $\log_2 n$ сравнения. Докажите, что этот алгоритм оптимален.

Задача 3. Рассмотрим два алгоритма выбора наименьшего из неравных чисел. Первый алгоритм: найти меньше из первых двух чисел, сравнить его с третьим, опять взять меньше, сравнить с четвертым и т. д. Второй алгоритм («кубковая» или «олимпийская» система): разбит числа на пары, меньше из каждой пары пропустить в следующий тур. Если одному числу не нашлось парного, то это число тоже пропустить в следующий тур. В следующем.type повторить то же самое и т. д., пока не останется одно число. Какой из этих алгоритмов требует меньше сравнения?

Задача 4. Докажите, что не существует алгоритма выбора наименьшего из n неравных чисел, который требовал бы меньше (n-1)-го сравнения. (Прием, использованный в доказательстве теории 2, позволяет доказать лишь то, что число сравнения в худшем случае не меньше $\log_2 n$.)*

Перейдем теперь к задаче упорядочения, что есть к задане расположения в ряд по возможности неравных чисел

$a_1, \dots, a_n$. Ответ важен, в частности, для решения на ЭВМ задач, связанных с поиском информации (мы уже видели, что упорядочность обеспечивает быстрый поиск).

Алгоритм $A_2$: упорядочивать по очереди начальные группы чисел данного совокупности: $a_1; a_1, a_2; a_1, a_2, a_3; \dots; a_1, \dots, a_n$ — последняя группа совпадает со всем совокупностью; для перехода от упорядоченной группы из i чисел к упорядоченной группе из (i+1)-го числа надо поместить $a_{i+1}$ на его место в имеющейся упорядоченной группе из i чисел — это место определяется при помощи алгоритма $A_1$.

Обозначим через $B(n)$ число сравнения, требуемое $A_2$. Имеем $B(n) = \log_2 2^l + \dots + \log_2 n \leqslant \log_2 2^l + \dots + \log_2 n + (n-2) = (2) = \log_2 n! + (n-2) \leqslant n(\log_2 n + 1) - 2$.

Задача 5. Определите число сравнения, требуемое следующим алгоритмом упорядочения $a_1, \dots, a_n$, найти наименьшее число и поместить его на первое место, затем найти наименьшее средние остатки и поместить его на второе место и т. д. (см. задачи 3, 4).

Задача 6. Допускается, что в неупорядоченной совокупности $a_1, \dots, a_n$ могут быть равные числа. Показите, что в этом случае алгоритм $A_2$ обеспечивает расположение данных чисел в порядке неубывания.

Прием, использованный при доказательстве теории 2, позволяет установить, что для любого алгоритма упорядочения можно подобраться совокупность $a_1, \dots, a_n$, применение к которой этого алгоритма потребует не менее $\log_2 n!$ сравнения (такой совокупностью будет одна из $n! = 1 \cdot 2 \cdot \dots \cdot n$ перестановок n произвольных чисел). Вместе с (2) это показывает, что во всяком случае, $A_2$ не далек по числу сравнения от оптимального (чero нельзя сказать об алгоритме из задачи 5): так, например, $\lim_{n \to \infty} (B(n) / \log_2 n!) = 1$. Различными авторами предпринялиись попытки доказать оптимальность $A_2$ и даже печатно сообщалось о якобы найdenном доказательстве. Позделе выяснили, что $A_2$ не оптимален: этот алгоритм требует всем сравнению для упорядочения пятей чисел, а на самом деле достаточно семи сравнений. Это непростой факт, хотя он допускает формулировку в виде задачи на взвешивание.
